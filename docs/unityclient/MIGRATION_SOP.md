# Cocos → Unity 严格迁移 SOP

> 本文件是 Unity 迁移唯一执行流程。`STATUS` 记录当前进度，模块文档记录证据，`UI_1TO1_STANDARD` 记录视觉细则；三者不得另建平行流程。

## 1. 不可违反的原则

1. 同一时间只处理一个模块；当前模块未达到本批目标状态，不得启动下一模块。
2. 先取证、再设计、后编码；Cocos 调用链、协议、资源和基准截图未锁定前，禁止凭文件名或 Unity 现状猜实现。
3. 旧 Lua `Controller/Logic/Data` 优先作为业务与权威状态；C# 只承载通用 Socket、字节流、Unity 节点、资源、动画和渲染适配。
4. 新模块默认禁止新增业务型 `Store/Catalog/Presenter`。确需新增时，必须在模块文档写明旧 Lua 无法复用的证据、边界和回收计划。
5. 每个界面、弹窗、Tab、可达关键状态必须有有效 Cocos 截图；Unity 单端截图不能证明视觉完成。
6. 协议成功不等于界面完成，主布局相似也不等于视觉通过；状态只能按门禁证据升级。
7. 发现版本、协议、资源或数据不一致立即停工定位，禁止用占位文图、伪造回包、错误历史截图继续推进。
8. 无法取得必要证据时标记阻塞；只有用户明确批准调整范围，才能跳过门禁，并必须记录未完成项。

## 2. 状态机

| 状态 | 必须满足 |
|---|---|
| `evidence-pending` | 尚未完成当前 Cocos 调用链和基准取证 |
| `evidence-ready` | G0-G2 证据与设计齐全，可以编码 |
| `logic-implemented` | 静态实现完成，尚未真实动态闭环 |
| `logic-validated-visual-pending` | 协议、状态、交互动态通过，尚无完整 Cocos 对照 |
| `visual-fixing` | Cocos/Unity 同状态截图齐全，正在消除差异 |
| `visual-1to1-complete` | G0-G6 全部门禁和证据通过 |
| `blocked` | 缺源码、资源、数据或可复现环境；模块文档已记录阻塞点 |

状态只能逐级升级。旧 `phase1-complete` 仅代表旧功能口径，不得解释为视觉完成。

## 3. 阶段门禁

### G0 范围冻结

必须输出：

- 模块名、入口按钮、功能 ID、目标页面、弹窗、Tab、关键状态清单。
- 本批包含项、不包含项、成功判定、允许的数据变更。
- 目标账号/角色、隔离角色策略、固定分辨率 `1334×750`。

门禁：范围未写入模块文档，不进入 G1。

### G1 Cocos 运行链取证

必须输出：

- 主入口 → Lua 回调 → `Utils:OpenFunction/InitUI` → View/Controller → 完整 CSB/CSD 路径。
- 写包/读包、协议号/op、`protocol.h`、`pack_deal.cpp`、成功/失败/空态/推送语义。
- 贴图、字体、Timeline、Imod、动态节点及实际动作号、循环、缩放、挂点。
- 每个目标状态的有效 Cocos 截图和逐步操作记录。

门禁：截图必须核对窗口、页面、账号、角色、步骤、尺寸和目标节点；任一不符立即作废。点击首次未进入目标页，停止坐标试错，转查代码、日志、协议或自动化。

### G2 迁移设计

必须输出：

- 旧 Lua 复用表：原文件、职责、保留方式、需要的兼容 API。
- C# Bridge 清单：仅列 Unity 平台能力，不写业务规则。
- Cocos 节点 ↔ Unity Transform 映射：路径、坐标、尺寸、锚点、层级、字体、交互。
- 状态矩阵和协议字段映射；明确权威源、渲染镜像和生命周期。

门禁：权威状态归属不清、节点映射不全、仍有版本猜测时，禁止编码。

### G3 静态实现

执行顺序：

1. 先补通用 Bridge/兼容 API。
2. 复用或最小改造旧 Lua 业务逻辑。
3. 接入真实 Prefab、资源、Timeline、Imod；原 Prefab 优先只读。
4. C# 只绑定节点和渲染 Lua 状态；占位文字、临时图和伪状态不得进入验收版本。
5. 先只读，再增量，再消耗/变更，不跨阶段混做。

门禁：静态编译、Lua 加载、资源引用和差异检查通过后进入 G4。

### G4 逻辑动态验收

必须覆盖：

- 入口、返回、正常、空态、失败、重复操作、服务端推送。
- 变更前后权威快照、重拉一致性、重连持久化、切号清理。
- 隔离角色、真实协议 SEND/RECV、严重异常扫描。
- `Run-UnityModuleValidation.ps1 -Module <name>` 对应模块门禁。

门禁：状态漂移、假成功、未解释异常或数据未恢复时不得进入 G5。

### G5 视觉对照

按 `UI_1TO1_STANDARD.md` 执行：

1. Unity 使用同账号、同数据、同步骤、同分辨率、同稳定帧截图。
2. 每个界面、弹窗、Tab、关键状态生成并排图、半透明叠加图、差异图和差异清单。
3. 逐项核对文字、图片、坐标、尺寸、层级、裁剪、按钮态、红点、Timeline、Imod 和交互。
4. 占位文字、错误图标、截断、重叠、公共层遮挡或资源语义不一致均判失败。

门禁：未解释差异为零并人工复核后，才能进入 G6。

### G6 回归与收口

必须通过：

- Bootstrap 两次语义幂等。
- Python UI 测试。
- Unity 编译、模块 Runner、严重异常扫描。
- `Test-UnityMigrationDocs.ps1` 和 Git 空白检查。
- 模块文档记录截图尺寸、SHA-256、命令、结果和限制；`STATUS` 只更新唯一实时状态。
- 关闭本阶段启动的 Cocos、Unity/Hub、`kapai.exe`、workspace MySQL，清理夹具。

门禁：以上证据齐全才标记 `visual-1to1-complete`。

## 4. 防跑偏检查

每次开始工作前回答以下 6 项，任一为“否”立即停止：

- 当前是否只有一个目标模块？
- 是否已锁定当前运行版本的真实 Cocos 调用链？
- 是否已获得本阶段需要的有效 Cocos 截图？
- 是否明确旧 Lua 的复用范围和权威状态？
- 当前修改是否只服务于已冻结范围？
- 上一门禁的证据是否已经写入模块文档？

出现以下情况必须回退到对应阶段：

| 发现 | 回退 |
|---|---|
| 页面、协议或 CSB 版本不一致 | G1 |
| 新增大量业务 C# 类 | G2，重新审查 Lua 复用 |
| 服务端结果与客户端状态不一致 | G1/G2，重查协议权威语义 |
| Unity 有占位文图或错误资源 | G3 |
| 只有 Unity 截图或错误历史图 | G1/G5 |
| 日志成功但 UI 错位、遮挡、截断 | G5 |
| 想切换下一个模块 | 先完成 G6 或记录阻塞并取得用户批准 |
