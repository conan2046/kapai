## 入口处理顺序

只处理 Unity 单机实际开放的入口；被 Unity 启动配置明确屏蔽的功能不纳入清理范围。对每个开放入口执行同一闭环：

1. 从游戏实际入口按钮定位回调、Presenter、Prefab/Catalog key、节点访问、ActionTag、Timeline 和导入配置。
2. 建立该入口会触达的按钮、Prefab、节点和依赖清单；把已有验收证据挂到对应行。继续追踪入口产生的自动跳转、弹窗、返回落点和条件分支；其中需要迁移的行为并入当前入口闭环，不拆成重复验收项。
3. 已验收且本次改动未影响其依赖的入口标为“跳过（已有证据）”，不得重复验收。若本次修改触及该路线依赖，只补验受影响的最小路线，不重跑已通过的其他路线。
4. 先迁移代码与导入配置。按本入口完整触达链一次性盘点全部 Prefab 的 `UiPrefabIdentity`、`CocosTimelinePlayer` 和旧 Timeline 轨道，再批量处理仅属于本功能且已无有效调用的旧组件/轨道。仍被其他有效入口使用的共享 Prefab 按 GUID 记录实际消费者并跳过；已屏蔽/不存在的功能只登记旧 Prefab 待删除，不重复做组件清理。
5. 编译后通过 Unity MCP 运行并从真实入口按钮走 EventSystem/Raycast 路线，检查节点、业务状态、SQLite 与 Console；记录 MCP 证据、问题 ID 与状态。截图/组件检查不代替视觉验收，画面正确性由用户最终确认。
6. 当前入口及其全部相关跳转/返回关闭后再进入下一个入口；共享依赖或 Timeline 仍被其他有效入口调用时保留其组件和轨道，并记录跳过原因、消费者和 GUID。
7. 入口闭环时再汇总涉及的 Prefab、节点、Timeline 和依赖变化；处理中只记录具体证据与未决问题，不用单个 Prefab 数量代表功能进度。

已不存在或 Unity 启动配置明确屏蔽的功能：跳过迁移与路线验收，只把对应旧 Prefab 路径/GUID 登记到上方“延后删除”清单；后续统一确认共享引用并删除。本轮不因功能缺席而清理仍被现存入口使用的共享 Prefab。
