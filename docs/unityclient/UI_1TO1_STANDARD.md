# Cocos → Unity UI 1:1 迁移门禁

本门禁适用于每个可见界面、弹窗和状态页。协议可用、Prefab 可打开、Unity 单端截图正常，只能证明功能链路成立，不能证明 UI 迁移完成。

## 1. 完成定义

同一账号、同一数据、同一分辨率、同一操作步骤下，Unity 必须与当前可运行 Cocos 版本一致：

- 使用同一代 Lua 调用链和完整 `csd/` 相对路径，禁止按文件名、旧截图或其他版本猜界面。
- 背景、图标、九宫格、按钮态、特效、Timeline/Imod 等优先复用原资源，不用临时纯色块或自制文字面板替代。
- 节点层级、锚点、坐标、尺寸、缩放、旋转、裁剪、层级、字体、字号、描边、颜色、对齐、间距一致。
- 初始、加载、空态、正常、锁定、红点、可领取、错误、弹窗、返回等实际可达状态逐一对照。
- 点击区域、按钮顺序、Tab/列表滚动、弹窗栈、返回流程、协议时机与动画起止一致。
- 动态时间、角色名等非确定内容只允许在差异报告中显式遮罩，禁止用大面积遮罩掩盖布局差异。

只有 `Cocos 基准 + Unity 对照 + 差异报告 + 人工复核 + 功能门禁` 全部通过，模块才允许标记 `visual-1to1-complete`。

硬门禁：每个可见界面、弹窗、Tab 和关键状态都必须有有效 Cocos 截图；Unity 修复后必须生成同账号、同数据、同操作、同分辨率、同稳定帧的对照截图及叠加/差异报告。不能只抽查模块首页，也不能用 Unity 单端截图证明完成。任何占位文字、错误图片、文字截断/重叠、层级遮挡或资源语义不一致均判定未通过。

## 2. 每个模块必须记录

模块证据文档固定增加“视觉 1:1 记录”，内容如下：

| 记录 | 必填内容 |
|---|---|
| Cocos 脚本 | 主入口、按钮回调、Controller/View、`createNode/createLayer`、写包/读包脚本及行号 |
| 操作步骤 | 从登录/主界面开始的逐步点击、所用账号/角色、前置数据、预期状态 |
| UI 资产 | 完整 CSB/CSD 路径、贴图、字体、Timeline、Imod、动态创建节点 |
| 节点映射 | Cocos 节点路径 ↔ Unity Transform 路径；坐标/尺寸/锚点/字体/层级/交互 |
| 状态矩阵 | 初始、空态、正常、锁定、红点、弹窗、错误等状态是否可达及证据 |
| Cocos 截图 | 固定 `1334×750`，每个状态一张，记录 UTC、账号、步骤编号 |
| Unity 截图 | 与 Cocos 相同数据、分辨率、步骤和截图时机 |
| 差异报告 | 叠加图/差异图、阈值、遮罩区域及理由、未通过差异清单 |
| 动态证据 | 协议 SEND/RECV、动画/交互断言、Console 严重异常、进程与夹具清理 |

建议证据目录：

```text
.local/ui-fidelity/<Module>/
  flow.md
  ui-map.json
  cocos/<state>.png
  unity/<state>.png
  diff/<state>.png
  report.json
```

`.local/` 证据不入库；模块文档必须记录最终文件名、尺寸、SHA-256、生成命令和结论。需要长期留存时再复制到明确的仓库证据目录。

## 3. 固定执行流程

1. 从当前启动入口打印 Cocos 实际调用链，锁定 Lua、CSB/CSD、协议与服务端分支。
2. 启动 Cocos 单客户端，按 `flow.md` 走到目标状态；用同一工具只截游戏窗口，不截桌面。
3. 关闭 Cocos；导出节点/资源/动画/交互清单并填写 `ui-map.json`。
4. 静态修复 Unity：原 Prefab 优先只读，运行时绑定必须复现 Cocos 节点语义，不另做替代 UI。
5. 启动 Unity 单客户端，使用同一账号数据、分辨率、步骤和稳定帧截图。
6. 生成逐状态叠加图和差异图；逐项修正，直到无未解释差异。
7. 再跑模块协议 Runner、Bootstrap 两次语义幂等、文档门禁、Python UI 门禁和严重异常扫描。
8. 更新模块文档、Manifest、STATUS；关闭 Cocos、Unity/Hub、`kapai.exe`、workspace MySQL，清理夹具。

## 4. 状态口径

| 状态 | 含义 |
|---|---|
| `logic-implemented` | 静态功能已接线，未完成真实动态闭环 |
| `logic-validated-visual-pending` | 协议/数据/交互已动态通过，但尚无 Cocos 视觉对照 |
| `visual-fixing` | 已取得 Cocos 基准，正在逐项修正差异 |
| `visual-1to1-complete` | 功能与视觉门禁全部通过，证据齐全 |

旧文档中的 `phase1-complete` 一律只解释为“旧功能口径第一阶段完成”，不得解释为视觉 1:1 完成。
