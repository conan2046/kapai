## 实际战斗流程判定顺序（r75最终实际代码）

按当前 `unityserver/src/fight.cpp`、`fight_combat_data.cpp`、`fight_combat_periodic.cpp`、`fight_combat_rules.cpp`、`combat_data.cpp`、`combat_equipment.cpp` 和 `hero_build_selection.cpp` 的调用顺序整理。最终运行证据仍以顶部验收状态为准；以下描述实际实现，不把未触发机制计为通过。

### 1. 正式数据、存档与入场

1. 正式工作簿通过既有导出链进入 `unityserver/config/json`，加载并校验绑定、效果、规则、事件策略、目标策略、周期、控制、套装、法宝与槽位定义。非法引用、冲突优先级等在加载阶段拒绝；不从推荐构筑说明反向生成战斗效果。
2. 战前选择沿 Unity 按钮 → Lua BuildController → 319/43查询、319/44保存。`bank_item` 中 ExtData8 的 `61000+hero` 保存选择：低2位分支、后3位策略，高3位保留。失败恢复内存及数据库旧值；战中不提供人工施法操作。
3. 正式入场执行 `CFight::AddPet`：先 `AddTmplNoLock` 建立成员、属性及已学技能，记录所属角色；仅对实际在线持有该神将的角色读取穿戴与战前选择。
4. `CombatSnapshotEquipment` 读取该神将当前出战位的真实装备/法宝UID，由正式槽位优先级排序、去重，同互斥族法宝择最高阶，再激活已开放效果；套装按实际部位计件，达到正式门槛才激活。词条经实际装备生成/属性与被动技能链进入成员，不能用推荐表替代穿戴。
5. `ReadBattleSelection` 解码并核验开放绑定，写入成员 `combatBranch/combatStrategy`。未选择、旧档或无效选择沿原版/原策略口径处理。战斗读取入场对象；本场不会因战后再改选择追溯改变已算结果。
6. 可选诊断 `PROJECTX_COMBAT_ENTRY_EVIDENCE` 在第一次 `CalculateFight` 之前记录实际成员分支/策略/词条档位/套装组/法宝/技能；默认关闭，不筛选目标、不执行事件、不消耗RNG、不修改状态。

### 2. 每回合准备与开场

| 顺序 | 当前实际动作 | 关键边界 |
|---|---|---|
| 1 | 清空本回合动作、协议缓冲和当前行动者；重置双方本回合战术使用标记、词条回合计数/金额 | 战斗级记录保留；每次自身行动的记录在后续 action_start 更新 |
| 2 | 加入本回合增援/召唤、显示对话，执行 TurnBegin 公共被动并合并协议 | 增援与对话在本回合行动表生成之前 |
| 3 | `GetAllUnitByOrder` 生成本回合单位顺序 | 当前循环消费此顺序；没有在每个单位行动前重新按速度排序 |
| 4 | 仅第0回合：分支开场战意 → 分支守护 → 装备开场战意；各存活成员 battle_begin | 同类数值与规则由正式表读取 |
| 5 | 所有成员 opening_snapshot 先完整执行 | 装备开场属性全部结算后，才逐成员执行原开场属性转移等被动 |
| 6 | 逐成员：原开场属性被动 → before_opening_action/按需action_start → 开场对全队/加属性类Buff被动 → 合并额外协议 | 死亡成员跳过 |
| 7 | 逐存活成员执行回合开始Buff/随机友方被动并合并协议 | 然后才进入正式行动循环 |

### 3. 单位行动前与自动选技

1. 先检查强制结束、任一方全灭，取行动表头并移除；跳过死亡成员。设置当前行动者，检查 `revivedAt + revived_action_block_turns`：受本回合复活禁行动限制者直接跳过，尚未扣其自然CD。
2. 执行“友方行动影响其他成员”，清本次动作缓冲、击杀表和死亡表，重置各成员“本次行动已获受击战意”。
3. `UserActBegin` 被动先结算周期状态及其他行动前效果；DOT可能致死/复活/净化，合并协议后再次检查行动者存活。
4. 当前规则在选技前执行 `DecAllSkillCD`；清本次命中序号/普通攻击命中标记，递增自身行动编号，派发 action_start，再执行行动时属性/减CD被动和行动Buff。
5. `GetOption` 先处理状态：不可行动 → 蓄力待发技能 → 昏睡 → 有效嘲讽目标的普攻 → 混乱/魅惑及其他原AI分支。状态强制行为优先于普通自动选技。
6. 有英雄技能角色配置时：策略0沿原战术技能（CD、战意、有效目标）→常规技能→普攻；策略1–5先计算真实友敌、伤员、控制、DOT、复活与有效性事实，再按正式策略优先级选择。战术战意余量及应急例外来自表；战术/常规可用性保持原查询顺序，不能额外选靶而多消耗随机数。
7. 技能目标沿原范围/状态过滤与随机选择，再执行正式目标策略的排序、同值规则及人数截取；复活目标还需通过公共与同源次数、技能专属记录、禁复活等资格条件。
8. 若无行动：只按当前路径递减本成员状态时长后继续下一个单位。有行动：记入行动表，执行行动/行动提高自身攻击等原被动，合并额外协议后才进行主动作。

### 4. 主动作、单次命中和受击

1. 普攻进入 `NormalButtle`；技能进入 `SkillButtle`。战术技能先扣战意并占双方对应本回合标记，实际施法失败则恢复原战意与标记。常规技能成功后加正式战意并派发 after_regular；普攻仅在真实命中产生扣血或吸盾时加战意。
2. 技能施法先派发 before_skill_cast，校验已学等级、主动配置、效果类型，执行该技能原成长记录；记录旧CD，仅根层设置新CD，失败恢复旧CD，二次技能不重置主技能CD。再按攻击、治疗/复活、蓄力、Buff或驱散类型进入各自执行器。
3. 攻击逐段/逐目标处理。`CalculateOnceAction` 先取得攻击方增伤/状态被动参数和防守方防御/受击被动参数，再进入 `BasicFightAction`。
4. `BasicFightAction`：校验双方存活 → 二次攻击旁观事件 → 记录目标原有盾 → before_attack及命中/暴击属性修饰 → 命中率上下限 → 抽命中。闪避写协议并派发 after_dodge，结束本次命中；不结算伤害、暴击和反击。
5. 命中后：landed_attack/owned_buff_hit → 普攻或该技能类型基础伤害 → 二次伤害倍率 → before_direct_amount → 非首段非反击的连击倍率 → 原特殊怪物规则/最低伤害 → before_critical → 原暴击抽取/倍率 → after_critical_roll → 物理受击免伤被动 → before_hp_change。
6. 非反击主动作依次找保护者：正式保护查询指定守护者 → 保护Buff → 原最低生命援护被动。保护者必须存活且非昏睡；分担先结算保护者、再结算主目标。分担受击战意按正式开关，不额外擅加。
7. 直接扣血进入 `CombatDirectHpDamage`：按正式穿盾比例拆生命直伤与盾压，处理护盾效率/消耗的整数换算，剩余伤害交 `DecreaseHp`；普通路径先吸盾，再按同生共死规则选目标分摊，最后实际改HP、累计伤害/治疗统计、处理死亡或即时自复活。
8. 以扣血前后差值计算实际HP损失（回疗后净损失不得为负）。随后依次派发主段命中、根层after_attack、非反击after_hit、反击击杀/反击伤害、目标实际直接失血和非反击直接击杀等事件；各事件自有根层/首段/实际正损失条件。
9. 再写暴击/伤害/吸盾/复活协议，执行原攻击方首段属性、攻击/击杀加Buff/治疗等被动，随后防守方受击被动；反震、吸血、盾破及受击派生沿各自现有路径结算。盾失造成的嵌套损失统计在当前相关Buff/破盾处理完成后汇总，避免使用尚未结束的事件损失。
10. 回到 `CalculateOnceAction` 后，只有根层、目标存活且非昏睡才判反击；正式before_counter可改概率/倍率，成功还须占公共追加攻击预算。普通反击保留原根层战意/盾失语义，用反击标记阻止再排一次普通反击；正式要求二次深度者进入对应深度。

### 公共规则的有意差异

已接入的公共规则覆盖双方与分支 0。相比集成前主线，同源同类盾按表刷新，所有盾共享目标生命上限比例；DOT 层数与持续时间受表约束。与来源分支保持上述规则语义。周期结算按来源分组，避免旧主线将不同来源聚合后错误归属；这会改变多源场景的伤害、吸血归属与预算。尚未完成旧分支可执行程序的固定种子差分，不能把公式抄录或局部回归当成完整一致性验收。

新增公共控制递减、复活和追加预算也覆盖基础分支/敌人。前期未消费的追加预算占位值为 2，本阶段核对来源 `fight_hero_build_equipment.cpp::HeroBuildTryExtraAttack` 后修正为 3；这是对占位值的纠正，与来源分支默认值一致。

直接伤害阶段将增伤属性从旧减伤乘区移到独立加伤乘区，并从旧位置移除，避免重复计算；新增上下限来自正式 combat_rule。此变化覆盖基础分支及敌人，与来源分支的该项语义一致。减伤合并后统一封顶 60%，忽防按剩余防御连乘后封顶 60%，并移除旧词条末尾再次乘伤害的路径。原分支的 float 计算后整数截断保留（例如 1000×33% 减伤结果 669）。这些是局部公式/定向验证，不是完整原二进制伤害链差分通过。
