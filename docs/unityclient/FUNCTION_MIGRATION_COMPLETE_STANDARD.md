# Unity 功能迁移完整标准

> 本标准高于“页面可打开、协议可返回、截图相似”。任何一个 Cocos 可达控件未闭环，模块都不得标记迁移完整。

## 1. 完整的最小验收单位

验收单位不是“页面”，而是：

`入口 → 页面 → 可操作控件 → 前置状态 → 点击/拖动 → 业务结果 → UI反馈 → 持久化/恢复`

每个 Cocos 当前版本可见或可达的按钮、列表项、Tab、装备槽、技能图标、关闭区、滑动区、红点和引导热区，都必须单独登记。只复制 Prefab、显示数据或让某个协议成功，不算该控件完成。

## 2. 单控件完成的 12 项硬门禁

| # | 验收项 | 必须满足 |
|---:|---|---|
| 1 | 节点 | Unity 中存在对应 Transform，位置、尺寸、锚点、层级和点击区域与 Cocos 一致 |
| 2 | 可操作性 | 真实 `Button.onClick`/事件已绑定；正常态可点击，禁用态不可点击，不能是装饰空壳 |
| 3 | 入口一致 | 必须从玩家实际入口点击到达，禁止测试直接调用内部 `Show/Open/Complete` 方法代替 |
| 4 | 前置条件 | 等级、功能开放、阵位、材料、货币、次数、锁定等判断与旧 Lua/服务端一致 |
| 5 | 业务行为 | 打开的页面/弹窗、发送的协议/op、参数顺序和本地状态变更与 Cocos 一致 |
| 6 | 权威结果 | 成功后以服务端回包/推送或旧 Lua 权威状态刷新，C# 不伪造成功和消耗 |
| 7 | 完整反馈 | Loading、按钮态、音效、点击效果、Toast、错误提示、确认框、红点变化全部一致 |
| 8 | 动画表现 | Pressed/Disabled、Timeline、Imod、特效、数值跳变和稳定帧语义一致 |
| 9 | 异常分支 | 空态、材料不足、非法参数、重复点击、超时、断线、服务端拒绝均有正确反馈 |
| 10 | 生命周期 | 重拉、返回、重进、重连、切号后状态正确；监听不重复注册，旧角色数据清空 |
| 11 | 双端证据 | 同账号、同数据、同步骤录制 Cocos/Unity 点击前、按下、结果、失败状态截图或视频 |
| 12 | 自动+人工 | 自动化从真实控件触发且断言结果；人工逐控件点击通过，二者缺一不可 |

12/12 才能把该控件标记为 `complete`。

## 3. 页面与模块完成规则

- 页面完成率 = `已完成控件数 / Cocos 在册控件数`，必须 `100%`。
- 页面中的动态列表，每类 Item 交互按正常、空、锁定、选中、禁用至少各验证一次。
- 一个按钮打开的子页、弹窗或二级功能未完成时，父页面不得标记完整。
- 暂不迁移的功能必须在版本范围中明确排除并从入口隐藏；“按钮可见但点击无效果”一律算缺陷，不能算排除。
- 模块完成要求所有页面、弹窗、Tab、返回路径及跨页状态 `100%`；任何可达空壳都会把模块状态降为部分迁移。

## 4. 允许使用的状态

| 状态 | 含义 |
|---|---|
| `shell-only` | 只有页面/资源，业务控件基本未绑定 |
| `read-only` | 权威数据可显示，但写操作和子流程未闭环 |
| `partial-interactive` | 部分真实控件可操作，控件矩阵未达到 100% |
| `functional-complete` | 所有在册控件和业务分支通过，尚未完成视觉/表现 1:1 |
| `visual-complete` | 功能完整基础上，全部状态视觉和动画 1:1 通过 |
| `migration-complete` | 功能、视觉、异常、持久化、自动化、人工验收全部通过 |

禁止再使用“第一阶段完成”“逻辑已跑通”“G6 通过”表达迁移完整。历史状态在逐控件重审前统一视为 `legacy-unverified`。

## 6. 新验收产物

每个模块必须提交一份控件矩阵，字段固定为：

`页面 | 控件路径 | 可见条件 | Cocos回调 | 协议/op | Unity绑定 | 成功反馈 | 失败反馈 | 重连结果 | Cocos证据 | Unity证据 | 自动结果 | 人工结果 | 状态`

Runner 必须读取此矩阵并验证：在册控件覆盖率 `100%`、真实点击覆盖率 `100%`、失败分支覆盖率 `100%`。覆盖率不足只能输出部分迁移，不允许输出 `COMPLETE`。
