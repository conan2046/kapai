## 2. 当前可运行规则

### 2.1 技能与战意

- 战意按双方队伍独立保存，范围 `0–100`。
- 普通攻击命中 `+8`，常规技成功释放 `+12`，单次行动首次受伤 `+3`，击杀 `+10`，友方阵亡 `+15`。
- 战法释放前检查共享战意；释放时扣除配置消耗。`TACTIC-03` 取同队最高减耗，最低消耗 20。
- `TACTIC-01` 取同队最高开场战意；`TACTIC-02` 增加常规技战意；`TACTIC-04` 在战意阈值以上减伤，施放战法后当回合关闭。
- 59 名神将只在其配置的常规技和战法之间选择。复活技必须存在阵亡友军，治疗技必须存在失血友军；条件不满足时回退常规技或普攻。
- 旧怪物和主角 AI 保持原逻辑；同时修正满血队伍仍随机施放治疗技能的问题。

### 2.2 装备词条

- 只有品质 6、7 装备生成特殊词条；品质 6 为 T1/T2，品质 7 为 T2/T3。
- 词条池按装备部位过滤。种子由装备 UID 与模板 ID 确定，同一旧装备迁移后结果稳定。
- 存档在旧主体尾部追加 `PXA1/version=1` 扩展块，不改变旧装备与法宝字段顺序；没有扩展块的旧存档在读取时自动补词条。
- 穿戴装备时，同一被动词条只注入最高 Tier，避免同名效果重复叠加。
- `/319 op=1` 原装备列表保持不变，新增 `/319 op=40` 单独下发词条元数据，旧客户端可忽略新操作码。

### 2.3 已接入战斗结算的词条

| 分类 | 已接入词条 | 结算点 |
|---|---|---|
| 护盾 | `SHIELD-01`～`SHIELD-04` | 护盾施加、实际吸收、破裂/到期、带盾行动结束；修正护盾不足时吸收量被错误清零的旧问题 |
| 治疗 | `HEAL-01`～`HEAL-04` | 溢疗、低血治疗、净化成功、复活成功 |
| 护卫 | `GUARD-01`～`GUARD-04` | 分担伤害、援护反击、嘲讽成功、开场团队保护 |
| 反击 | `COUNTER-01`～`COUNTER-04` | 反击实伤、反震实伤、反击命中、大额受伤 |
| 暴击 | `CRIT-01`～`CRIT-04` | 低血猎命、未暴击蓄锐、过量击杀溅射、击杀冷却 |
| 连击 | `COMBO-01`～`COMBO-04` | 后续段增伤/命中、击杀后下一追击强化、连击战意 |
| 破防 | `BREAK-01`～`BREAK-04` | 对盾增伤/越盾、破盾易伤、法防穿透、破盾或驱散战意 |
| 控制 | `CONTROL-01`～`CONTROL-04` | 开场速度排序、控制延长、抵抗补偿、受控目标增伤命中 |
| 持续伤害 | `DOT-01`～`DOT-04` | 毒层扩散、灼烧结束结算、异常目标增伤、DOT 实伤回复 |
| 减益 | `DEBUFF-01`～`DEBUFF-04` | 禁疗治疗延迟、易伤伴随降防、负面计数增伤、驱散后攻速提升 |
| 死亡/召唤 | `DEATH-01`～`DEATH-04` | 自身阵亡保护、任意阵亡成长、动态入场快照强化、死亡禁锢延长 |
| 战意 | `TACTIC-01`～`TACTIC-04` | 开场、常规技、战法消耗和高战意减伤 |

S6 后正式随机池开放 `1–48` 全部词条，旧存档中此前未开放的合法词条也不再被清退。直接伤害/治疗事件统一使用 `EFOT_Passive` 写入扩展战斗消息，不触发暴击、连击和二次吸血。

### 2.4 旧战斗引擎适配

- 旧引擎没有独立行动条，`DEBUFF-01` 的行动延迟映射为一回合等值速度降低；策划万分比保持不变。
- `DEATH-01` 的团队防御提升使用既有临时减伤通道承载，避免修改客户端 Buff 枚举和旧协议。
- `DEATH-03` 只强化实际动态加入阵位的援军/召唤物，不增加数量；使用入场时队伍最高同名词条快照。
- `CONTROL-03` 在旧主动 Buff 必中规则下不会虚构“抵抗”，只响应被动减益命中判定的真实抵抗事件。
- `COMBO-02` 复用旧引擎的后续攻击标志承载追击增伤与命中；击杀溅射会显式重选最低生命合法敌人。

### 2.5 S7 锁定、重铸与推荐

- `/319 op=41` 切换特殊词条锁定状态；锁定只保留词条类型，不锁定 Tier。
- `/319 op=42` 由服务端权威扣费并推进 `affixSeed`。未锁定时重新随机词条类型和 Tier；锁定时保留类型、只重铸 Tier，且保证结果 Tier 与重铸前不同。
- 品质 6 装备未锁定/锁定重铸分别消耗 `30000/60000` 金币；品质 7 分别消耗 `50000/100000` 金币。Steam 单机版不设置每日次数。
- 操作回包固定包含结果、提示、下一次费用和完整词条记录；Cocos、Unity 均以该记录更新模型，随后再接收 `op=40` 权威快照。
- Cocos 与 Unity 装备详情根据 `SHIELD/HEAL/GUARD/COUNTER/CRIT/COMBO/BREAK/CONTROL/DOT/DEBUFF/DEATH/TACTIC` 标签显示 12 类流派推荐，并提供锁定与重铸按钮。
- 每次队伍战意实际变化都复用 `EFOT_Passive` 行动显示 `战意 ±N（当前值/100）`；没有新增战斗行动枚举，旧客户端解析结构保持不变。

### 2.6 S8 首批神将配装参考

- 主配置为 `server/config/json/hero_build_profile.json`，Cocos 使用 `ConfigData/hero_build_profile_dat.lua`，Unity 使用 `Configs/hero_build_profile.json`；三份数据由回归逐字段核对。该配置仅用于配装参考，服务端战斗不读取它。
- 覆盖女娲、接引、准提、孔宣、多宝、金灵、哪吒、杨戬、黄飞虎、太乙、帝辛、吕岳，共 12 名神将 / 24 套 A/B 方案；名称必须与 `hero_skill_role.json` 一致。
- `core_affixes` 为核心词条键，匹配得 100；`support_tags` 为兼容词条类别，匹配得 60；其余得 0。分数仅表示**单件词条适配度**，不计算基础战力、Tier、套装或整套构筑完成度，也不代表实际增伤百分比。
- 已穿戴装备按展示阵位定位佩戴者，展示其 A/B 两种配装参考；未穿戴装备从首批方案中按“评分降序、配置 ID 升序”列出前三项。未知神将、空词条和无匹配词条均有明确降级文案。
- 推荐内容使用独立可变高度滚动行，避免把长文案塞进原有固定描述区；重铸权威回包刷新时同步重算推荐。
- 本轮不修改存档、协议、技能倍率或战斗行为，不提供技能 A/B 分支切换。`strategy_hint` 只是阅读建议，不会自动应用为战斗策略。
- 旧设计中的主题套装名与现行客户端装备套装名尚未统一，本轮不虚构映射；普通副词条、套装主题重整和可选技能分支仍是后续任务。

## 3. 关键兼容合同

- `equipment_affix.json` 固定 48 行，ID `1–48`，被动技能 ID 固定为 `5000 + affixId`。
- `hero_skill_role.json` 固定 59 行，常规技与战法必须来自角色原始前两个主动技能。
- 所有百分比均按万分比存储；战意、层数、回合和 CD 为整数。
- Cocos 与 Unity 都只渲染服务端下发结果，不在客户端重新随机词条。
- `affixSeed`、`specialAffixId`、`specialAffixTier` 和 `affixLockMask` 已进入存档；S7 重铸直接更新这些字段，重登不会恢复旧结果。
