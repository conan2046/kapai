# 统一任务类型与事件类型核对稿

本稿记录分类、事件语义与已落实的 Steam 范围筛选。网页和统一工作簿已按本文的四类任务更新；服务端配置和运行代码未改。数据基于当前仓库及 `E:\neiwang_kapai\concept` 的策划源表。下文“服务端加载”仅说明配置进入代码，不等于 Steam 玩家可以进入该玩法，也不等于事件一定能产生。

## 一、先分清四种编号

| 编号或字段 | 实际含义 | 策划模型中的位置 |
|---|---|---|
| `mission_config.kind` | 旧任务的主线、支线、日常、跨服大类 | 任务类型的历史参考；该表当前未加载 |
| `daily.type`、`sevendays.type` | 原界面列表/活动页分组；七日表的 `type` 不参与服务端 `InitQuestCfg` 解析 | 任务包或展示分组，不直接当统一任务类型 |
| `EMQCT_n`、`daily.condition[0]`、`sevendays.condition[0]` | 同一套现行任务事件编号 | 事件目录；目标值和附加参数跟随具体任务引用 |
| `EMISS_DC_n` | 旧任务系统的目标编号，与 `EMQCT` 是不同空间 | 迁移映射，须按语义、产生点和参数核对后归并 |

参考游戏的 `TaskPackage.TaskType` 说明任务类型应表达业务规则；`TaskDesc` 的 103 条描述模板同时包含事件、统计口径、过滤参数和文案。不能把其模板编号直接等同于本游戏的 `EMQCT` 事件编号。

## 三、现行事件目录的来源和覆盖

| `EMQCT_16/17` 副本星数 | 可研究同一“副本星数”状态指标加主线/支线参数 | 两者现行表均未引用，未检出直接产生点；缺少运行数据验证 |
| `EMQCT_14/36` 法宝搜索/寻宝 | 暂不合并 | 14 是 Steam 法宝搜索的现行成功事件；36 名称为“寻宝”，未查明是否同一玩法，旧 Lua 中另有 NPC 寻宝链 |

| `EMISS_DC_9` 与 `EMQCT_2` | 招募事件跨旧/新空间的归并候选 | 两边有 C++ 调用，仍需核对成功时机和覆盖招募方式 |

## 四、给网页和 Excel 的字段合同

当前网页与 Excel 使用以下字段合同：

1. **任务类型**：类型 ID、中文名、业务规则说明、默认接取方式、默认重置/期限规则、适用范围、平台范围。任务包、旧列表组、周期和入口单独配置。
2. **事件类型**：统一 ID、中文名、业务动作或状态、成功产生时机、计量方式（增量/当前值/最高值等）、计量单位、可用参数及范围、服务端产生点、平台范围、核对状态、旧编号别名。
3. **任务条件实例**：阶段（触发/完成）、所选事件 ID、指标、筛选参数、比较符、目标值、计数起点及窗口、逻辑组合。奖励不参与事件去重。
4. **页面限制**：纳入 Steam 的未定义事件可选入任务草稿，供策划补齐条件；事件合同未完成或未验收时，引用它的任务不能标为已验收。入口待核对项显示但禁用，屏蔽项不进入策划目录。

- `server/src/mission_manager.h`：`EMissionType`、`EMISS_DC`、`EMQuestCondType` 定义。
- `server/src/mission_manager.cpp`：`InitQuestCfg` 同时读取 `daily.json` 和 `sevendays.json`；`InitJiJinCfg` 的读取主体被注释；`CheckQuestState` 区分累加、筛选、当前值和专项查询；`UpdateQuestState` 同时分派普通目标和七日目标。

- `E:\neiwang_kapai\concept\data\excel\xml配置表\新表\daily.xlsx` 的 `Sheet2`：事件编号、示例配置与参数说明。
- `docs/unityclient/STEAM_SCOPE.md`：Steam 的七日、基金、帮派、竞技场、血战等入口范围。
- 用户提供的 `任务配置.xlsx`、`任务事件.xlsx`：任务类型与带参数的目标描述模板分层参考，不作为本游戏正式枚举来源。
