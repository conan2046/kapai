# 统一任务系统：旧数据迁移预览

审计页只读 `E:/neiwang_kapai/concept/data/excel` 中的旧任务与剧情 Excel，以及当前工作区的服务端 JSON、XML、Lua。编辑页维护独立的统一 Excel 源表 `data/unified-quest/UnifiedQuest.xlsx`，不会写回旧表或 Unity 工程。

```powershell
python tools/unified-quest-viewer/viewer.py --port 8892
```

打开 `http://127.0.0.1:8892/` 进入审计页；`http://127.0.0.1:8892/editor` 进入统一任务编辑器。审计页刷新会重新读取旧源文件，不会启动 Unity。

编辑器以任务配置为入口，支持八张 Excel 源表、中文表单、记录搜索、新建任务、事件目标、固定状态对话槽、对话组逐句维护、保存前校验、Excel 下载和前后端 JSON 导出。任务类型固定为主线、支线、日常、累计；底层 ID 等字段收在“高级字段”中。每条任务固定有“未接取前”“已接未完成”“已完成未领取”三个对话槽，各槽只填写对话表组 ID；组内可维护多句对白，也可复用同一组。保存时先写临时工作簿，回读校验通过后替换正式文件，旧版本保留在 `outputs/unified-quest/backups/`。正式导出只收“已验收”；预览导出可收“草稿”并在 JSON 中标记 `preview_only=true`。原始奖励配置仅保留引用，不参与事件去重。

“下载策划核对表”生成独立的 `任务策划核对表.xlsx`。各页采用项目 Excel 的四行表头：英文字段名、`all`、中文说明、数据类型；第 5 行开始是配置。任务一行汇总数字任务 ID、任务类型 ID、完成事件 ID、重复周期 ID、目标数量及三个数字对话组 ID，不重复填写任务类型和事件名称，也不导出任务归属范围与打开入口。现有 `daily.N` 对应原表数字任务 ID `N`；新增任务使用未占用的数字 ID。任务类型 ID 为主线 1、支线 2、日常 3、累计 4；重复周期枚举 ID 为一次 1、每日 2、累计 3，定义在独立“重复周期”页。事件参数 ID 是所属事件内的数字序号，任务引用时须同时按完成事件 ID 定位。任务事件的分类、计数方式、单位、生效范围、定义状态与 Steam 范围均使用数字 ID，查“通用枚举”；事件触发时机和计数文字移到“事件说明”，参数范围与说明移到“事件参数说明”，任务类型规则移到“任务类型说明”。名称与对白仍为文本内容。`EMQCT_` 旧枚举仅出现在“旧编号对照”。策划核对表是从技术源表生成的快照，修改须在网页保存；“下载技术源表”保留八张关系表，供系统读写和数据核对。`EMQCT_` 编号来自服务端 `EMQuestCondType` 枚举，`daily.xlsx.condition` 第一位沿用该数值；部分中文事件名及参数描述是迁移梳理时形成的草稿，需按“定义状态”区分原始代码注释和策划定义。

任务表的筛选三列仅在事件有额外筛选参数时填写：`筛选参数ID` 用完成事件 ID 到“事件参数”页查同事件的参数 ID（参数用途 ID 为 2）；`筛选比较ID` 查“筛选比较”页；`筛选值` 按“事件参数说明”的可配置范围填写。目前只有事件 34 的“产物品质”定义了筛选参数，其事件内参数 ID 为 2、建议比较 ID 为 1（大于等于）、可填整数 3–7；当前 130 条任务没有启用筛选，三列均留空。当前策划核对表只支持整数筛选值；将来增加文本筛选时须同时扩展表结构和校验。

左侧“策划配置”按任务、任务类型、事件类型和迁移核对排列。`EventType` 是 `EMQCT` 定义与 `daily.xlsx.condition` 第一位的去重合集；任务完成条件引用该事件类型，并填写目标值及附加筛选值。事件参数随类型编辑，同页显示引用该事件的流程节点与源任务条件。物理 Excel 仍分 `EventType`、`EventParam`、`QuestType`、`Quest`、`QuestCondition`、`QuestNode`、`DialogueLine` 和 `LegacyMap`，便于导出与引用校验。Steam 屏蔽事件仅保留迁移审计；纳入范围的待定义事件可进入任务草稿，须补全触发时机、计数规则、单位、归属范围及参数并完成验收后才能正式导出。`EMISS_DC` 属于另一套旧目标编号，只保留在迁移审计。

`daily.xlsx.type` 的 `0/1/2/3` 是旧任务列表分组，保存在任务的“旧列表分组”字段，不作为统一任务类型。主线和支线目前没有导入的可发布任务；已导入的日常 19 条、累计 111 条均为草稿。三个对话槽由任务状态决定，不在事件目标前后顺序插入。类型与 Steam 范围核对见 `docs/UNIFIED_QUEST_TYPE_EVENT_REVIEW.md`；游戏内任务状态与对白播放尚待验收。

当前机器的 Excel 写入运行时已连接到 `.local/unified-quest-viewer/node_modules`。若换机器运行，需要将它连接到 Codex bundled Node 依赖，并确保有 Node.js 与 `@oai/artifact-tool`；只读审计不依赖这一步。导出文件保存在 `outputs/unified-quest/export/`。

“任务与条件”页按完成条件类型或旧任务目标类型汇总配置。列表与详情使用中文字段名；条件值按源表条件字典拆解，原始英文列名和数值可在详情底部展开核对。任务分类的 `0/1/2/3` 尚无经过验证的业务名称，页面保留为“分类 0/1/2/3”。

## 已知边界

- Excel、JSON、XML 做结构化逐行读取；每日任务逐字段核对正式 Excel 与服务端 JSON，当前 148 条差异为 0。NPC 与道具脚本核对正式 Excel 和当前 JSON 导出的脚本编号差异。服务器实际从数据库取值，运行库尚未核对。
- Lua 页先展示 Steam 功能按钮到协议、服务端与 Lua 的代码链，以及 `unityserver/script` 与原脚本的哈希核对；再逐文件列出任务 API、附近函数、任务编号、旧目标编号、通用数据槽、NPC/道具/场景源表、C++ 固定编号入口和对话回调。静态入口线索与运行时可达性必须分开判断；阶段结论见 `docs/UNIFIED_QUEST_LUA_AUDIT.md`。
- “事件候选”按 `EMQCT` 与 `EMISS_DC` 分开列出源表引用、C++ 直接调用和 Lua 常量引用。零命中只表示当前静态扫描未找到该调用形式，不等于运行时不可达。
- 旧任务及旧剧情标注“历史休眠”依据是服务端加载入口已注释；此结论不延伸到同名或关联的 Lua 脚本。
- 现行任务事件类型与旧任务目标类型分属不同编号空间，不能按数字自动去重。
- `EMQCT` 有 59 个旧事件编号。`daily.json` 的 148 条任务引用 19 种，`sevendays.json` 的 130 条任务引用 22 种，合并实际使用 38 种；当前网页显示两表引用数。Steam 范围标注为纳入 39、屏蔽 16、待核对 4；任务条件下拉框显示 43 种未屏蔽事件，其中 39 种可用于草稿、4 种显示但禁用；39 种中 9 种已写参数合同。工作簿有 10 条参数定义、4 种任务类型、130 条任务草稿、130 条事件引用条件、780 个流程/固定对话节点、34 句对白和 630 条旧编号审计映射。34 句来自 10 个章节对话组；组 `10042` 有 1 行完全重复，导入时已去重，原表未改。`daily.xlsx` 没有对白字段，故 daily.9 等任务的三个状态槽默认都不绑定组 ID。旧剧情组的 Steam 播放入口未确认，不自动绑定任务。全部任务仍为草稿，尚无运行期验收。
